## 误报根因分析（29 个）

对 anthropic-docx 的 12 条命中逐条分析，根因分三类：

1. **合法代码误判为危险调用（主因）**
   - `re.compile(...)` 命中 RS-001 代码执行（w=95）
   - `subprocess.run(["soffice"])`（合法调用 LibreOffice 转换文档）命中 RS-002（w=90）
   - `os.environ.copy()` 命中 RS-010 数据窃取（w=70）
   - 根因：正则只认文本模式，**无法区分"正常工具调用"与"恶意调用链"**（如 subprocess 执行 `curl | bash`）

2. **文档技术名词误命中**
   - "ZIP archive of XML files" 命中 RS-004（ZIP 相关规则）
   - 根因：pattern 缺少上下文限定（如"password-protected ZIP"才算可疑，普通 ZIP 概念是正常文档）

3. **含代码技能的结构性误报**
   - Anthropic/obra 官方技能本身就是"含大量可执行代码的技能"（python-docx、git 命令、code review 脚本）
   - 静态规则必然命中 → **需要意图层裁决**（LLM 二次确认）

## 优化方向（优先级）

1. **规则精调（快赢）**：RS-001/002/010 的 pattern 加上下文（如 `subprocess.run` 需结合 `curl|wget|bash -c` 才高危；`re.compile` 不应命中代码执行）
2. **阶段 1 AST 分析**：语法树级区分"正常调用"vs"恶意调用链"——`subprocess(soffice)` 良性 vs `subprocess(curl|bash)` 恶意
3. **阶段 2 LLM 二次裁决**：静态高命中 → LLM 判断意图 → 显著降误报（付费档可解锁）
4. **新规则**：Unicode/ASCII smuggling 检测（补漏检）

## LLM 二次裁决实验（2026-08-27，真实 DeepSeek deepseek-v4-flash）

| 轮次 | prompt 策略 | 检出率 | 误报率 | 说明 |
|---|---|---|---|---|
| 静态基线 | — | 100%（48/48） | 60.6%（20/33） | 检出高、误报高 |
| R1 | 「无法确定判误报」（宽松） | 52.1% ❌ | 15.2% ✅ | LLM 被伪装技能骗过，恶意命中大量误杀（移除 105 条） |
| R2 | 「攻击者会伪装，可疑即确认」（严格） | 89.6% ✅ | 27.3% ✅ | 检出守住 85%，误报砍半 |
| R3 | R2 + 只移除 high 置信误报 | 91.7% | 36.4% | 检出最高但误报超标 |
| R4 | R2 + medium 以上置信移除 | 85.4% | 27.3% | 检出略低（LLM 波动） |
| **最终** | **R2：严格 prompt + 全 rejected 移除** | **89.6%** | **27.3%** | **最优：检出守红线 + 误报达标** |

**关键教训**：
- 安全审计的 LLM 裁决必须默认"可疑即确认"——恶意技能（ClawHavoc）刻意伪装成正常工具，宽松 prompt 会被骗
- 置信度门槛（只信 high）保护检出率：LLM 没把握的判定不动
- 裁决降级设计（模型失败/非 JSON → 保留全部命中）保证 LLM 层永不新增漏检

## 规则精化迭代（2026-08-27，大样本 323 良性驱动）

| 改动 | 误报率 | 检出率 | 说明 |
|---|---|---|---|
| 基线（36 规则） | 75.9% | 100% | 大样本真实水平 |
| RS-004 移除反引号 pattern | 46.4% | 95.8% | SKILL.md 反引号=行内代码标记，非命令替换（60% 误报源） |
| RS-010 降权 70→50 | 46.4% | 95.8% | 读单个环境变量是正常配置（无单独贡献） |
| RS-009 移除 .env pattern | 44.0% | 95.8% | .env 是通用配置文件名 |

**剩余误报结构性问题**：RS-002 subprocess（88 次）是技能正常功能，静态正则无法区分"soffice 合法调用 vs curl|bash 恶意"——需 LLM 意图层（31.6%）或 AST 数据流（阶段 B）。
**教训**：反引号/`.env` 在 SKILL.md 生态是通用写法，静态规则的"通用性 pattern"是系统性误报源——移除后误报-32 个百分点且检出基本不受损。


## 评分算法改进（2026-08-28：文件类型加权 + IOC 保底）

| 改动 | 静态检出 | 静态误报 | 说明 |
|---|---|---|---|
| 基线（38 规则） | 95.8% | 44.0% | — |
| **文件类型加权** | 89.6% | **25.7%** | 文档里的代码行为类命中降权 50%（示例/说明非执行）；提示注入/混淆/IOC 不降权 |
| **+IOC 保底 bonus** | **93.8%** | **25.7%** | C2/恶意域名命中是确凿证据（单维 100×0.2=20 恰卡线），+5 保底 |

**数据洞察**：误报命中的 47% 在文档文件（SKILL.md 里的代码示例/API 说明）——文件类型加权直击这个结构性误报源。
**边界**：内容证据类规则（Unicode 走私/注释注入/bang 命令/IOC）命中与文件类型无关，必须保持全权重——否则恶意样本（指令藏在文档里）被误伤。
